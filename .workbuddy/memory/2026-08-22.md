## 后端启动与数据播种（已完成）
- `sql/postgresql-default-data.sql` 是**空文件**（上游占位符，只有2行注释），默认数据靠后端启动自动播种
- 首次 `gow run admin` 失败：PG 密码认证失败(28P01)。根因：**宿主机 127.0.0.1:5432 被原生 Windows PostgreSQL 服务抢占**（postgres.exe PID 5864 + pgagent，随系统自启），Docker 的端口转发被抢占。netstat 见两 PID 监听 5432
- 解决：不动原生 PG，把 Docker PG 改映射到 **15432**（改 docker-compose.libs.yaml ports + data.yaml source port=15432），`docker compose up -d --force-recreate postgres`
- 重启后端报菜单播种失败：`menu: invalid enum value for module field: MODULE_UNSPECIFIED`。根因：`pkg/constants/default_data.go` 的 ComponentToModule 对 BasicLayout/"" 返回 MODULE_UNSPECIFIED，但 Ent schema menu.module 枚举无此值（仅 DASHBOARD/OPM/SYSTEM/DICT/TENANT/PERMISSION/LOG/INTERNAL_MESSAGE/FILE/TASK）
- 修补 `backend/app/admin/service/internal/service/menu_service.go`：syncMenuTree + createDefaultMenus 两处，映射到 UNSPECIFIED 时置 m.Module=nil（字段本就 Optional+Nillable）。加 identityV1 导入。重置 DB 后重启 → 菜单播种成功（33 条）
- 后端监听 :7788(HTTP)/:7789(SSE)，Swagger http://localhost:7788/docs/ 返回 200
- 登录 API：POST /admin/v1/login（不是 /auth/login），需 X-Captcha-Id/X-Captcha-Value 头，缺验证码返回 400 "invalid or missing captcha"（认证链路正常）
- 演示数据：导入 `sql/postgresql-demo-data.sql`（307行真实数据：租户/组织/字典/套餐；自带 tenant_admin 用户密码同为 admin）。最终：2 用户、2 角色、33 菜单、15 组织、5 字典、1 租户
